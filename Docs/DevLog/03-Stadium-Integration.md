# 03 · Stadium 모델 적용

## 2026-11-12 · 경기장 교체

1. **적용 대상** — BaseballPrototype 씬의 기존 Board와 Stadium.fbx, Field_BaseColor.png.
2. **적용 이유** — 사용자가 가져온 경기장 모델과 텍스처로 실제 플레이 공간을 교체한다.
3. **구조 · 설계값** — Assets/FullCount/Prefabs/Stadium.prefab은 FBX의 중첩 프리팹을 참조한다. 동봉 임포트 도구의 앵커 정렬 방식을 적용한 뒤 Y축 -45° 회전과 0.2828427 배율로 홈을 (0,0,0), 1루를 (4,0,4), 3루를 (-4,0,4)에 맞췄다. 투구점은 모델의 PitchAnchor를 따라 (0,0.181,6)이다. 필드 표면은 Y=0이고 외야는 +Z다.
4. **장단점** — 모델의 인쇄 라인·베이스와 실제 관통 구멍을 그대로 사용할 수 있다. 이번 FBX의 홈 배치는 수비 7개, 외야 HIT/OUT 5개, 파울 2개로 이전 외야 9칸 설계와 차이가 있다. 기존 1:1 비율 대신 가져온 모델의 형상과 비율을 우선 적용했다.
5. **구현 과정 · 실제 구현** — 기존 Board와 그 자식 표식을 씬에서 제거하고 Stadium 프리팹 인스턴스를 배치했다. 동봉 도구의 색상 구분에 맞춰 URP Lit 머티리얼 8개와 바닥 텍스처를 연결했다. 바닥과 벽 등 메시 23개에 Convex가 꺼진 정적 MeshCollider와 기존 구름 물리 머티리얼을 적용했다. 관통 구멍은 메시 형상대로 열려 있다. 투구 경로의 표면은 레이캐스트로 확인했다. 고정 탑뷰 카메라에 경기장 전체와 하단 버튼의 여백을 확보했다. Blender가 설치되지 않은 환경에서 .blend 임포트 오류가 발생해 원본과 메타 파일을 SourceAssets/Stadium/으로 옮겼다.
6. **개선 사항** — 실제 구멍은 존재하지만 낙하 판정, 점수, 아웃·파울 처리와 공 자동 회수는 후속 단계다. 모바일 실기기 검증도 후속으로 진행한다.

## 검증 결과

- Unity 6000.3.27f1의 열려 있는 원본 프로젝트에서 Play 모드를 실행했다.
- 기존 Board 제거와 Stadium 인스턴스, 홈·1루·3루 앵커 정렬, 투구 경로의 바닥 연결을 확인했다.
- 홈 방향 직구 속도 5 유닛/초를 확인했다. 스윙 시점을 달리했을 때 타구 속도는 약 (-3.83,1.24,9.28), (-1.14,0,8.35)였으며 수평 방향 차이는 14.69°였다.
- 투구·스윙 버튼 잠금과 스윙 도중 리셋, 필드 이탈 위치에서 리셋, 위치·회전·선속도·각속도 복구와 재투구를 확인했다.
- 최종 카메라 크기는 12.525232이며 실제 메시 꼭짓점 범위에 맞춰 여백을 정했다. 가로 16:9 Game 뷰에서 경기장 전체와 세 버튼을 확인했다.
- 최종 씬을 새 Play 세션으로 실행해 실제 마우스로 투구·스윙·리셋 버튼을 눌렀다. 투구 진행, 배트 회전, 버튼 잠금과 시작 상태 복구를 확인했고 콘솔 오류는 0개였다. 검증 후 Play 모드를 종료했다.
